# 강사 업무 개선 우선순위 — 2026-10-21

브랜치: codex/teacher-workflow (main 0422a1e 기준). 사용자 요청에 따라 별도 브랜치에서 진행하며, 메인 병합·배포는 하지 않는다.

## 구현 순서

1. 집중 검토: 기존 검토 필요 필터·문항별 비교에 답안별 집중 모드, 단축키, 미저장 진행 상황, 저장 안전장치를 추가한다. 반복 판정과 스크롤 부담을 줄이는 첫 구현 범위.
2. 할 일 모아보기: 실제 미채점·검토 대기 데이터를 회차/반별로 집계하고 해당 작업으로 바로 이동한다. 미래 일정은 미완료 업무로 세지 않고, 자료 없음·답안 없음·확정 대기를 구분해야 한다.
3. 이전 회차 설정 복사: 배점·채점 규칙·출제 비율을 복사한다. 학생 답안·성적·발송 기록은 복사하지 않는다. 기존 데이터 덮어쓰기는 미리보기를 제공한다.
4. 일괄 입력: 출결·과제·점수의 키보드 이동, 붙여넣기 검증, 선택 범위 변경 및 되돌리기.
5. 작업함: 업로드·분석·채점의 상태와 실패 부분 재시도. 실제 작업 수명·재진입 요구를 정한 뒤 저장 구조를 설계한다.
6. 변경 이력·전달 반영: 누가 무엇을 수정했는지와 이미 전달한 결과와의 차이를 보여준다. 보관 범위/개인정보/확정 시점을 정한 뒤 migration을 함께 작성한다.

## 1차 구현 수용 기준

- 기존 목록·정답/오답 판정·명시적 저장 기능을 유지한다.
- 실제 검토 대상만 안정적인 순서로 모은다. 결석·미응시·미입력·확정·무효/전원 정답은 집중 판정에서 제외한다.
- 판정 후 다음 미판정 답안으로 이동하고 이미 판정한 답안으로 돌아가 수정할 수 있다.
- 키보드 판정은 명시적 지정이며 반복 입력으로 판정이 해제되지 않는다.
- 저장 전에는 서버에 쓰지 않는다. 목록 복귀/실패 시 임시 판정을 보존한다.
- 저장 중 입력을 잠그고, 회차 변경 시 이전 임시 판정을 제거한다.
- 저장은 기존 grade-confirm API를 사용한다. AI 호출·스키마 변경 없음.

후속 2~6은 우선순위 계획이며 이번 턴의 완료 기능으로 보고하지 않는다.
