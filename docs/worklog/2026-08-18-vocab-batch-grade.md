## 1. 일괄 사진 채점

한 학생씩 사진 채점(15~20초 × N명, 강사가 붙어 있어야 함)이 번거롭다는 문제.

**흐름** — 채점 그리드 상단 「단어 시험지 일괄 채점」 → 다이얼로그
1. 사진 여러 장 드롭/선택 (이미지·PDF)
2. 장당 압축 → 이름란 판독 (동시 3, 장당 1~2초) → 학생 자동 매칭. 확신도 점: 초록(high) / 노랑(low) / 회색(직접 선택)
3. 매칭 표 확인 — select 로 수정. 미매칭은 채점 제외, 같은 학생 2장이면 시작 버튼 잠금, 결석 학생 비활성, 기채점 학생 있으면 덮어쓰기 confirm
4. 「N명 채점 시작」 → **학생당 별도 요청**, 동시 3. 행별 진행/점수 실시간, 그리드 점수 즉시 갱신
5. 실패 건 재시도 버튼

**파일**: [vocab-batch-grade-dialog.tsx](../../src/components/grade/vocab-batch-grade-dialog.tsx) · [grade-grid.tsx](../../src/components/grade/grade-grid.tsx)(버튼) · [vocab-photo-name/route.ts](../../src/app/api/weeks/[id]/vocab-photo-name/route.ts) · [anthropic.ts](../../src/lib/anthropic.ts) `readVocabSheetName`

**설계 결정 / 부작용 가능 지점**
- 채점 요청을 학생당 분리한 건 **Vercel Hobby 60초 제한**(요청당) 때문. `maxDuration = 300` 은 Hobby 에서 무시되지만 무해. 서버 채점 API 변경 없음 → 개별 사진 버튼과 같은 코드 경로.
- **이름 매칭은 잘못 매칭 < 미매칭.** 세 가지 시도 후 채택:
  - 명단만 주고 고르게 → 명단에 없는 이름도 가장 비슷한 학생에 억지로 붙임 (실측: 김테스트 없으면 정하은/high) → 폐기
  - 명단 없이 자유 판독 → 한글 손글씨 오독(김테스트→징혜스트) → 폐기
  - **채택**: 명단을 읽기 힌트로 주되 rawName(보이는 그대로)·name(명단 매칭) 분리 보고. 코드가 정확 일치→high, rawName↔name 한 글자 이내→low, 그 외 null. 실측 명단에 있음→high, 없음→null.
  - 남은 약점: 명단에 한 글자 차이 이름이 있으면 모델이 그쪽으로 읽어 high 가 날 수 있음 → **강사 확인 단계가 필수**인 이유. 같은 반에 한 글자 차이 이름은 드묾.
- 진행 중 다이얼로그가 닫혀도(새로고침 등) **이미 날아간 요청은 서버에서 끝까지 돌아 점수는 저장됨** — 화면만 잃음. 남은 학생은 다시 넣으면 됨.

**닫기 동작** (`86cead7`) — 복원 대신 실수 방지 쪽을 택함:

| 상태 | X / 바깥 클릭 / 취소 / Esc |
|---|---|
| 빈 상태 · 전부 완료 | 바로 닫힘 |
| 사진 넣고 매칭 확인 중 | confirm "넣어둔 사진 N장이 사라집니다" |
| 채점 중 | 안 닫힘 |
| 완료 · 실패 남음 | confirm "실패 N건이 남아 있습니다 (완료된 M명 결과는 이미 저장됨)" |

**검증**: 크롬 확장 CDP 가 모달에서 멈춰 headless Chrome + CDP 로 9단계 시나리오 전부 통과 (열기·매칭 → 수동 선택 → 중복 잠금 → 결석 비활성 → confirm → 동시 3 채점 중 X 무시 → 완료 4·실패 1 → 재시도 → 닫기 거절/수락 → 재오픈 초기화). 이 검증이 잡은 버그 1: 썸네일 URL 해제 effect 의 deps 가 `[items]` 라 채점 진행마다 이전 썸네일이 깨지던 것 (`6ffd9c0`).

## 2. 사진 압축 + 30일 삭제 (`a97b47f`)

지난번 Storage 용량 초과의 실제 원인 후보 — 폰 사진 원본(3~6MB)이 학생당 매주 그대로 저장. 백업 정리만으로는 부족.

- [image-compress.ts](../../src/lib/image-compress.ts): Canvas 로 **긴 변 1600px · JPEG 80%**. 개별 버튼·일괄 채점 둘 다 압축본을 이름 판독·채점·Storage 저장에 재사용. PDF·디코딩 실패(HEIC 등)는 원본 통과.
  - **정확도 실측**: 34/34 나온 시험지를 7단계 압축(원본 268KB → 1000px 54KB)해 채점 → **전부 34/34**. 1600 은 여유를 둔 값. 이 원본이 깨끗한 렌더 이미지라 실전보다 불리한 조건이었음.
  - 실전에서 흐린 사진 오독이 늘면 `IMAGE_COMPRESS_MAX_LONG_EDGE` 를 2000 으로.
  - 브라우저 실측: 1588px PNG 248KB → 1131×1600 JPEG 152KB. 폰 사진 기준 약 1/15.
- [vocab-photo-retention.ts](../../src/lib/vocab-photo-retention.ts): `vocab-photos` 버킷에서 `updated_at`(재채점 시 갱신) 기준 30일(`VOCAB_PHOTO_RETENTION_DAYS`) 지난 파일 삭제. **매일 백업 cron 끝에** 붙임 — 실패해도 백업엔 영향 없음.
  - 지워진 사진은 정오표 "원본 사진" 버튼이 404 → 안 뜸 (`vocab-photo-url` 이 이미 처리).
  - Storage `list()` 는 접속 실패해도 빈 배열을 줄 수 있음 — 그 경우 아무것도 안 지움 (안전한 쪽).
- **저장 경로를 확장자 없이 `{weekId}/{studentId}` 로 변경** (퀴즈에서 잡음): 예전엔 `.jpg`/`.png` 가 경로에 붙어 png→jpg 재채점 시 파일이 2개가 되고 upsert 가 안 됐다. 이제 진짜 upsert. 재채점 시 구 형식 잔여(`.jpg`/`.png`)도 같이 remove. 기존 DB 의 `vocab_photo_path` 는 옛 경로 그대로라 읽기엔 영향 없고, 다음 채점부터 새 경로.
- 용량 전망: 15명 × 4주 × 0.3MB ≈ **20MB 상시**.
