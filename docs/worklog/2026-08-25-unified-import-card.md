# 2026-08-25 — 가져오기 UI 통합: 카드 1개 + 문서 유형 자동 감지 (Phase C 중간안)

"일반 해설지 업로드"와 "시험지 가져오기(문제지/정오표 2단)"로 갈라져 있던 업로드 UI 를
**카드 1개·드롭존 1개·버튼 1개**로 통합. 완전 자동 판별은 오판 비용 때문에 배제하고,
감지는 **기본값 제안까지만** (사용자가 보이는 상태를 고칠 수 있음).

## 1. 동작

| 올린 파일 | 처리 |
|---|---|
| PDF 2개 | 순서대로 시험지/정오표·해설 역할 뱃지 (화살표로 교환) → 기존 원클릭 체인 |
| PDF 1개 · 이미지들 | 라디오 3택: 시험+해설 일체형(→ parse-answers 통짜) / 문제만(→ 청크 구조 파싱) / 정오표만(→ 정답 반영, 문항 저장 후에만 활성) |
| 그 외 조합 | 인라인 에러 (PDF 3개+, PDF+이미지 혼합) |

- 단일 PDF 선택 즉시 백그라운드 업로드 + `import-plan {mode:'detect'}` → **감지 결과가
  라디오 기본값** ("감지: 해설이 포함된 문서로 보입니다"). 스캔형(텍스트 없음)은
  confident=false → 기본 해설 포함 + "직접 확인" 안내.
- 감지 때 올린 스토리지 경로를 시작 시 재사용 — `parse-answers` 에 storagePath 지원 추가
  (재업로드 없음 + 4.5MB body 한도 우회). 서버가 소비하므로 재시도는 base64 폴백.
- 파일은 누적 선택 (시험지 고른 뒤 정오표 추가 선택 가능).

## 2. 감지기 — `detectExplanationSection` (LLM 0콜, 순수 함수)

마커: "정답 및 해설" 헤더(숭문형) · `{해석}{풀이}{어휘}` 류 섹션 마커(예열TEST형 —
**실측에서 초기 버전이 놓쳐 보강**) · "1. 제목 ⑤" 번호+유형+정답기호 라인 · 오답 분석 등.
실물 4개 PDF 검증: 숭문·예열·서울여고 → 해설 포함(confident), 용산고 44p → confident
false(추출 실패) → 안전 기본값. 실물 텍스트 축약본 기반 유닛테스트 4개.

## 3. E2E (실 LLM, 개발 DB)

| | 고3 예열TEST → 2주차 | 고1 숭문 Week4 → 1주차 |
|---|---|---|
| 통짜 해설지형 경로 | 141s | 209s |
| 결과 | 6/6 문항·정답·해설 | 17/17 (소문항 1a~1c, find_error, 서술형 포함) |
| AI 해설 안전망 | 0건 (원본 해설 우선 — 과금 0) | 0건 |

**관찰**: 해설 일체형은 여전히 통짜(원래부터 whole)라 7p=209s. ~10p 초과 문서가 실제로
나타나면 분할 파서(문항부 청크 + 해설부 정오표식 파싱)가 필요해지는 기준선 — 사용자
결정으로 **가드 없이 유지**, 실수요 확인 시 착수.

## 4. 부작용 가능 지점

- 레거시 UI 제거: parseMode select("자동 판별/해설 포함")·접이식 카드·2단 카드 소멸.
  실행 경로 3개는 전부 유지 — 입구만 통합.
- 감지 실패(fetch 에러 등)는 조용히 무시 — 기본값만 못 채울 뿐 사용자가 라디오로 선택.
- 단일 PDF 선택 시 즉시 임시버킷 업로드 — 시작 안 누르고 이탈하면 잔여물 (기존 정리
  백로그와 동일 부류).
- 발견한 기존 잠복 버그(별도 태스크): 해설지 원본 저장 경로가 파일명뿐이라 주차 간
  동명 파일 덮어쓰기 가능.

## 수동 확인

- 단일 해설 PDF: 감지 문구 + "시험+해설 일체형" 기본 선택 → 시작 → 완료 후 문항/정답
  편집 탭 확인.
- 시험지+정오표 2개: 역할 뱃지 + 순서 교환 + 「한 번에」 버튼.
- 문항 저장 전 "정오표만" 라디오가 비활성인지.
