# 2026-08-25 — 해설 일체형: 분할 실험 기각 + 해설 보완을 클릭 안 자동 단계로

## 1. 분할 파서 A/B 실험 — 기각 (실측이 결정)

"확신 조건부 분할"(문항부 청크 + 해설부 정오표식 파싱)을 실제로 만들어 같은 숭문 PDF 로
통짜와 A/B 비교했다:

| | 통짜 | 분할 |
|---|---|---|
| 총 시간 | **209s** | 323s |
| 문항 | 17행 (소문항 분리, find_error) | 15행 (소문항 뭉개짐, 유형 다운그레이드) |
| 해설 | 17건 원본 | 9건 원본 + 6건 AI 대체 (추가 opus 과금) |

원인: ① 문항부가 경계 정렬로 1청크가 되어 병렬 이득 0, ② 이 PDF 는 pdf-lib 슬라이스가
백지가 되어 페이지 렌더 폴백(이미지 입력 = 느린 콜), ③ 해설부는 문항 저장 후에만 가능
(직렬), ④ 해설부 파서 매칭 누락 → 드레인 추가 과금. **분할 코드는 전부 롤백** (git 에
이 커밋 직전 상태로 남아 있어 대형 문서 수요가 실증되면 복원 가능).

## 2. 수확 ①: `slicePdfRangeSafe` — 기존 백지 청크 버그 수정 (유지)

실험이 잡아낸 실버그: **일부 PDF(숭문 등 폰트 구조 특이)는 pdf-lib copyPages 슬라이스가
전 페이지 백지가 된다** → 문제지형 청크 경로에서 LLM 이 빈 배열 반환 = 조용한 0문항.
원본 범위에 텍스트가 있는데 슬라이스에서 사라지면 unpdf 페이지 렌더(PNG)로 이미지 PDF 를
재조립하는 폴백을 [week-reading-import.ts](../../src/lib/week-reading-import.ts)
`slicePdfRangeSafe` 로 추가 — 문제지형·정오표 청크 파서 모두 이 방어를 받는다.
(실측: 숭문 5p 렌더 재조립 11s, 이후 파싱 정상 15문항)

## 3. 수확 ②: AI 보완 해설을 같은 클릭의 자동 단계로 (버튼 없음, 전 문항 무조건)

기존엔 `parse-answers` 가 파싱(실측 209s) + 인라인 해설 생성까지 **한 함수 300초** 안에서
했다 — 해설 빈 문항이 많으면 천장 초과 위험. 이동:

- 서버: `parse-answers` 에서 해설 생성 제거 (파싱·저장만).
- 클라: 두 업로드 흐름(해설 일체형·정오표)이 저장 성공 직후 `explanations-drain` 을
  자동 반복 호출 (`drainExplanations` 공용 헬퍼). 진행 문구 + 보완 수 토스트.
- **정책 변경 — 업로드 직후 드레인은 `includeExisting` 모드**: 원본 해설이 있어도
  전 문항을 AI 로 다시 쓴다 (사용자 결정 — 문제은행발 해설이 한 줄짜리인 경우가 많고,
  예전 「AI 해설 생성」 버튼을 사실상 매번 눌렀음). 프롬프트에 기존 해설을 넣어
  "부정하지 말고 통합·확장" 지시 → 원본의 정답 근거는 보존된다.
- includeExisting 모드는 빈 해설 기준으로 진행을 알 수 없어 **offset 커서**로
  페이지네이션 (서버가 attempted 반환, 클라가 누적).
- 실패해도 정답 반영은 유지 (멱등).

## 4. 해설 미생성 복구 칩 ([explanation-drain-chip.tsx](../../src/components/grade/explanation-drain-chip.tsx))

드레인 도중 탭이 닫히면 해설 구멍이 남는데 재트리거 진입점이 없던 문제. 주차 화면
상단에 **빈 해설 문항이 있을 때만** 나타나는 칩 추가 — 노출 판정은 이미 캐시되는
`useExamQuestions` 재사용 (LLM 0콜), 클릭 시 남은 문항만 드레인(missing 모드).
E2E: 해설 1건 비움 → 칩 노출 → 클릭 → 상세 해설 생성·저장 → 칩 소멸 확인.
평상시(해설 완전)엔 렌더 자체가 없다.

**비용 주의**: includeExisting 정책으로 업로드마다 전 문항 opus 생성이 돈다
(17문항 ≈ 3배치 ≈ 1~2분). 원본 해설 그대로 쓰고 싶은 문서가 생기면 이 지점을
옵션(체크박스)으로 되돌릴 것.

## 부작용 가능 지점

- `parse-answers` 응답에서 `explanations_generated` 필드 제거 — 참조하는 클라 코드 없음 확인.
- 렌더 폴백은 청크당 렌더 시간(페이지당 ~2s)과 페이로드 증가를 수반 — 백지 PDF 에서만 발동.
- 개발 DB 3주차의 분할 실험 잔여 데이터는 삭제 완료 (1·2주차 통짜 결과는 유지 — 정상 데이터).

## 수동 확인

- 숭문류 PDF 를 "시험지+정오표 2개" 흐름으로 올렸을 때 백지 청크 없이 문항이 나오는지
  (safe slice 경로 — 콘솔에 `[slicePdfRangeSafe] 슬라이스 텍스트 유실` 경고).
- 해설이 일부 빠진 해설지 업로드 시 완료 전 "부족한 해설을 AI가…" 단계가 자동으로 도는지.
