# 백오피스 반 보관·학습기간 UX 분석

## 범위와 결론

사용자 요청: 백오피스의 기기 설정 메뉴를 라이트/다크 토글로 변경. 지난 반 보기와 학습기간 관리의 도입 이력 및 기능을 확인하고 재설계 방향을 먼저 분석.

결론: 반 보관과 학습기간은 서로 다른 기능이며 둘 다 필요하다. 현재는 목록 필터, 과거 조회, 공유 기본 범위 변경, 운영 설정이 비슷한 이름과 과한 화면 비중으로 섞여 있다. 일상 조회와 운영 변경을 분리해야 한다. 이번에는 테마만 구현하고 반·기간 화면/API는 변경하지 않았다.

이 문서는 Git 이력·UI·훅·API·마이그레이션을 읽은 결과다. 운영 DB 상태나 실제 사용자 클릭 빈도는 확인하지 않았으며, 사용 빈도 판단과 배치 제안은 제품 목적에 근거한 설계 판단이다.

## 실제 기능 구분

| 기능 | 실제 동작 | 사용자에게 알려야 할 영향 |
|---|---|---|
| 지난 반 보기 | `includeArchived=1`로 현재 반과 보관 반을 함께 조회 | 지난 날짜만 조회하거나 보관 반만 조회하는 기능이 아님 |
| 반 보관 | `class.archived_at` 기록 | 기본 반 목록·여러 반 선택기에서 제외. 학생 공유/재시험 접근에도 영향 |
| 반 복원 | `archived_at=null` | 일반 목록으로 복귀. 다른 접근 조건이 충족되면 공유 대상에도 복귀 |
| 반 삭제 | 반 레코드 삭제 | 보관과 다름. 기존 확인 문구는 관련 데이터 전체 삭제를 경고 |
| 기간 생성 | 기간 추가, 기본적으로 현재 기간 지정, 이전 현재 기간 종료일 조정 | 공유 기본 성적·오답·단어·과제 범위와 주차 표시 변경 |
| 기간 수정 | 이름·학기·시험 구분·날짜 수정 | 날짜로 회차 소속을 계산하므로 기존 기록의 표시 범위도 달라짐 |
| 현재로 전환 | 다른 기간의 현재 표시 해제, 선택 기간의 종료일을 null로 변경 | 단순 조회가 아니라 운영 기준·날짜를 바꾸는 작업 |
| 기간 삭제 | 기간 구분 레코드 삭제 | 수업·성적·출결 자체는 남지만 기간 선택 및 주차 구분에 영향 |
| 단어 CSV/인쇄 | 반 상세의 현재 기간 날짜로 단어 필터 | 기간 변경은 공유 화면에만 영향을 주는 것이 아님 |

반을 보관해도 백오피스 상세에 진입해 기록을 읽을 수 있으며, 현재 상세는 읽기 전용으로 잠기지 않는다. 보관을 삭제나 읽기 전용과 같은 뜻으로 안내하면 안 된다.

## 현재 UX의 구체적 문제

### 수업 목록

1. **이름과 동작 불일치:** ‘지난 반 보기’는 보관 반만 보여주지 않는다. 버튼을 누르면 현재/보관 반이 생성일순으로 섞인다. 날짜가 지났어도 직접 보관하지 않으면 현재 목록에 남는다.
2. **상태가 다음 동작 문구로만 표현됨:** ‘현재 반만 보기’ 버튼을 보고 현재 화면이 ‘전체’임을 역으로 추론해야 한다.
3. **보조 작업의 비중이 큼:** 보관 반 조회가 상단에서 수업 생성과 나란히 상시 노출된다.
4. **모바일·키보드 접근성:** 카드 관리 버튼이 `opacity-0 group-hover:opacity-100`이다. 터치에는 hover가 없고 키보드 포커스 시 가시성도 보장하지 않는다. 편집/삭제/보관이 아이콘뿐이며 접근 가능한 이름도 없다.
5. **영향 설명 누락:** 보관 아이콘 클릭은 즉시 저장된다. 단순히 목록 정리라고 생각한 조작이 학생 공유에 영향을 줄 수 있다.

### 반 내부 학습기간 관리

1. **매일 할 일이 아래로 밀림:** 큰 설명 패널·색상별 설명 상자 3개·전체 기간 목록이 학생 목록과 수업 일정 위에 상시 노출된다. 기간이 늘수록 화면이 길어진다.
2. **제품 용어가 불분명함:** ‘학습 기간’, ‘시험 기간’, ‘현재로’, ‘SHARE 표시 기준’이 섞인다. 특히 ‘현재로’는 내가 과거 데이터를 조회하는 것인지 학생에게 보이는 기본값을 바꾸는 것인지 불명확하다.
3. **조회와 수정이 붙어 있음:** 목록 각 행에 전환·편집·삭제가 노출된다. 현재 화면에는 조회용 기간 선택과 설정 변경을 명확히 분리한 조작이 없다.
4. **설명 중복:** 데이터가 지워지지 않는다는 설명과 범위 변화 설명이 기본 화면·생성창·확인창에서 반복된다. 필요한 영향 정보는 저장 직전 실제 날짜·회차 수로 보여주는 편이 낫다.
5. **원리 이해를 요구함:** 시작일 변경이 이전 기간 종료, 주차 재번호, 공유 범위를 동시에 바꾼다. 사용자가 날짜 규칙을 직접 추론해야 한다.
6. **정보 자체는 필요함:** 수업일 빠른 선택, 첫 포함 수업, 영향 회차 수, 잘못 만든 기간 수정·복구는 버릴 기능이 아니다. 적절한 단계로 옮겨야 한다.

## UI 변경 전에 정리할 동작

### 과거 기간 조회를 ‘현재로’로 처리하면 안 됨

현재 활성화 API는 선택 기간의 종료일을 제거한다. 예를 들어 A=1월, B=2월 이후인 상태에서 A를 다시 현재로 만들면 A는 1월 이후, B는 2월 이후로 남아 날짜가 겹칠 수 있다. 기존 현재 기간의 시작일보다 앞선 날짜로 활성화하면 `closeCurrentPeriods`가 B의 종료일을 자르지 않는 코드 경로가 있다.

공유 조회는 날짜 포함 여부(`isWeekInPeriod`)로 수업을 고르고, 주차 이름은 겹치는 기간 중 시작일이 가장 늦은 기간(`getPeriodForWeek`)으로 만든다. 따라서 겹치는 기간에서는 조회 범위와 표시 기간명이 어긋날 가능성이 있다. 이는 코드 경로로 확인한 위험이며 운영 데이터 발생 여부는 확인하지 않았다.

후속 구현에서는 다음을 분리해야 한다.
- **기간 조회:** URL/화면 필터만 바꾸고 DB를 수정하지 않음.
- **새 기간 시작:** 다음 운영 구간 추가와 이전 구간 경계 조정.
- **공유 기본 기간 변경 또는 잘못된 전환 복구:** 날짜 경계를 어떻게 유지할지 정한 후 명시적으로 저장. 기존 활성화 API를 이름만 바꿔 재사용하지 않음.

기간 삭제는 현재 UI에서 현재 기간을 막지만 API에는 같은 조건이 없다. 기간 저장도 여러 요청으로 나뉘어 중간 실패 시 현재 기간이 해제된 채 남을 수 있다. 운영 변경 UI를 개편할 때 서버 검증·원자적 처리도 함께 점검할 항목이다.

## 권장 화면 구성

### 수업 목록: ‘운영 중’이 기본, 보관은 보조 조회

상단은 `수업 목록 / 운영 중 N개`와 `수업 만들기`. 그 아래 작고 명확한 `운영 중 ▾` 상태 선택을 둔다. 선택지는 운영 중 / 보관된 반 / 전체이며 현재 선택을 그대로 표시한다. 지금처럼 ‘지난 반 보기 → 현재 반만 보기’로 버튼 의미를 뒤집지 않는다.

보관된 반은 그 상태로 분리해 보고 필요할 때 복원한다. 카드에는 항상 보이는 `더보기` 버튼 하나를 두고 수정·반 보관·삭제를 배치한다. 보관 시 ‘일반 목록에서 제외되고 학생 공유 접근도 중단된다’는 실제 영향만 짧게 확인한다. 보관 기능이 공유 종료까지 담당해야 하는지 정책을 바꿀 경우에는 UI 축소와 별도로 다룬다.

### 반 상세: 현재 상태는 한 줄, 관리는 별도 패널

반 이름 바로 아래에 `학습기간  2학기 중간 ▾` / `공유 기본` 표시와 `기간 관리` 보조 액션만 둔다. 학생·수업 일정이 곧바로 이어진다. 상시 설명 카드 3개와 전체 기간 관리 목록은 제거한다.

- 기간 선택: 해당 기간 수업을 조회. 기본 공유 기간은 바뀌지 않음을 구분한다. 전체 수업 옵션과 원래 보던 기간으로 복귀하는 경로 유지.
- 기간 관리: 데스크톱은 우측 패널, 모바일은 충분히 긴 설정을 읽을 수 있는 전체 높이 패널. 단순 선택과 긴 편집 폼을 같은 작은 바텀시트에 넣지 않는다.
- 관리 패널 첫 화면: 기간명·날짜·포함 회차·공유 기본 표시, `새 기간 시작`, 각 행 `더보기`에 수정/기본값 변경/삭제.
- 새 기간: 다음 시험을 기본 제안, 기간명과 첫 수업일을 입력. 확정 직전 이전 기간 종료일·새 기간 첫 수업·학부모 기본 화면 변경을 한 번 보여줌. 고급 학기/시험 구분은 필요할 때 수정 가능.
- 용어: 학습기간(상위 개념), 새 기간 시작(생성), 이 기간 보기(조회), 학부모 기본 기간으로 지정(운영 변경). 구현상 날짜 수정이 동반되면 그 영향까지 명시.

## 이번 테마 변경

백오피스는 데스크톱 우측 하단, 모바일 헤더 우측에 라이트/다크 토글을 배치했다. 기존 사이드바·모바일 메뉴의 기기 설정 메뉴는 제거했다. 기존 system 설정은 현재 렌더된 색을 기준으로 첫 토글부터 light/dark를 명시 저장한다. share의 기존 테마 메뉴와 인쇄 라이트 고정은 유지한다. 이번 변경은 커밋·푸시하지 않았다.

검증: `npm run check -- --maxWorkers=2 --minWorkers=1` 통과. 타입·린트 오류 0, 기존 린트 경고 23, 47개 파일·650개 테스트 통과. 자동 설정에서 토글 시 명시적 라이트/다크 저장과 인쇄 경로의 기존 동작을 검증했다. 실제 백오피스 브라우저 배치는 이번 분석에서 확인하지 않았다.
