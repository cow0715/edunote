후속 `share-guided-analysis.html`은 최신 홈 동선 시안의 분석 화면만 보완했다. 홈 구성과 기존 기능 보존 요구사항은 유지한다. 이번 후속분은 별도 검토를 위해 커밋하지 않은 상태로 남긴다.

1. 먼저 볼 유형과 짧은 이유 → 관련 오답 조회.
2. 전체 유형별 가로 막대: 오답률과 오답/출제 수를 함께 표시.
3. 회차별 작은 막대: 정답률과 실제 정답/출제 수, 날짜를 함께 표시. 0%는 막대 높이 0으로 표현.
4. 영역별 정답률 비교를 하단에 유지.

유형 오답률은 낮을수록, 영역/회차 정답률은 높을수록 좋은 서로 다른 지표이므로 제목과 단위를 명시했다. 2회차의 가상 데이터로 방향을 보여 주는 예시이며 향후 성취를 예측하거나 장기 약점을 확정하지 않는다.

검증: 구문 및 렌더 전환 검사, 회차 값 0/2→2/3 및 2/2→2/3, 유형 조건을 유지한 문제 진입/복귀 확인. 브라우저 375px 뷰포트에서 가로 넘침 없음 및 유형별 오답 연결 확인. 실제 앱 변경·배포·사용자 테스트는 수행하지 않았다.

## 승인 후 실제 분석 탭 구현

사용자가 간결한 분석 시안의 구현을 요청했다. “함께 짚어볼까요?” 말투를 유지하며 유형·수치·상태별 안내는 실제 데이터로 결정한다. 사용자 목적은 최근 수업과 기간 누적 기록을 쉽게 읽고 시험·오답을 편하게 확인하는 것이다.

- 분석 순서를 제안 → 유형별 오답률 → 최근 두 출제 회차 비교 → 영역별 정답률로 변경했다. 레이더를 제거하고 얇은 막대·작은 비교 선을 사용한다.
- `buildShareAnalysis`는 선택 기간의 reading 답안만 집계한다. 출제 수를 고려하는 기존 Wilson 정렬을 사용하며, 오답이 없는 유형도 보여준다. 중복 태그와 다른 회차 ID를 구분한다.
- 모든 정답·미분류 오답·결과 미등록·소표본 안내를 구분한다. 유형 미분류 오답에는 전체 오답 조회를 연결한다.
- 기존 `useShareModel`에 연결했고 유형별 액션은 실제 태그 ID로 기존 `TagDrawer`를 연다. 데이터 조회 API나 DB 스키마는 변경하지 않았다. API가 선택 기간 score ID의 정답·오답을 모두 조회하는 것을 코드로 확인했다.
- 유형 8개/변화 3개 이후도 더 보기로 접근할 수 있다. 기간 누적 수치·회차별 전체 기록·기존 패턴 설명은 펼침에 유지한다. 미출제 회차는 0%로 만들지 않는다.
- 영역 집계에서 같은 문항의 여러 태그가 동일 영역에 속할 때 중복으로 세던 부분을 고쳤다.
- 홈의 최근 수업/기간 요약과 추이 그래프, 기록·시험·오답·단어 기능은 유지했다. 이번 변경은 분석 탭 중심이다.

검증: 실제 컴포넌트와 모델에 가상 데이터만 넣은 임시 로컬 QA 화면으로 375px 라이트, 320px 다크, 긴 유형명 줄바꿈, 추천 → 유형 오답(3건) → 닫기, 전체 회차 기록 펼침을 확인했다. 브라우저 콘솔 오류 없음. QA 파일/서버는 종료·제거했다. 운영 데이터와 배포 환경에서의 E2E 확인은 수행하지 않았다.

첫 전체 검사에서는 새 테스트 10개를 포함해 648개가 통과했으나 기존 테마 전환 테스트 1개가 5초 제한을 초과했다. 타입·린트 오류는 없었다. Node 24.19.0에서 `npm run check -- --maxWorkers=2 --minWorkers=1`로 재실행해 타입 검사, 린트(오류 0·기존 경고 23), 47개 파일·649개 테스트 전체 통과를 확인했다. 테마 테스트나 시간 제한은 수정하지 않았다. `git diff --check`도 통과했다. 이번 구현은 커밋·배포하지 않았다.
