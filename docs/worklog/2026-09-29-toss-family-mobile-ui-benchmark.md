# 토스 계열사 모바일 웹 벤치마크와 EduNote share 재설계 검토

조사일: 2026-09-29. 기존 ‘기간 선택 바텀시트 유지 + 오답 상세 전체화면’ 제안은 보류한다. 이 문서는 조사와 설계 가설이며 적용 완료된 사양이 아니다. 앱 코드와 design.md는 변경하지 않았다.

## 1. 조사 범위와 증거

[토스 회사 소개](https://toss.im/company)의 계열사/그룹 목록, [공식 브랜드 리소스](https://brand.toss.im/), [공식 채용](https://www.toss.family/career/jobs)의 목록을 합쳐 토스 본체와 아래 10개 계열사·서비스의 공개 홈페이지를 열었다. 회사 소개에 등장하는 VCNC는 소비자 서비스 타다로 확인했다. 브랜드·채용 목록에 포함된 토스인사이트도 추가했다.

‘모든 계열사’의 범위는 이 공식 목록에서 확인한 공개 웹사이트다. 해외법인·특수목적법인까지 법인등기상 전수를 검증한 조사는 아니다. 로그인 후 금융 앱, 상담 제출, 결제, 계좌개설은 조사하지 않았다. 각 홈페이지의 모든 하위 페이지를 전수 검사한 것도 아니다.

- 실제 브라우저: 390×844 모바일 뷰포트에서 홈·메뉴·대표 상세 화면의 스크린샷과 접근성 트리를 관찰했다.
- 공식 문서: 토스 디자인팀의 메뉴 컴포넌트 실험 및 TDS 개선 글, 공개 BottomSheet 문서를 읽었다.
- 현재 EduNote: share-client, home-tab, tag-drawer 및 앞선 복습 QA/구현을 비교했다. 이전 임시 로컬 QA 주소는 이제 리포트 없음으로 표시되어, 이를 최신 share의 정상 실화면으로 취급하지 않았다.
- 첫 렌더 이후 구조가 달라지는 사이트가 있어 초기 접근성 트리만으로 모바일 동작을 확정하지 않았다. 열림 애니메이션 중 캡처도 최종 형태로 판정하지 않았다.
- 메뉴의 모양과 동작을 확인한 조사다. 사이트별 접근성·성능·전환율이 우수하다고 입증한 것은 아니다.

## 3. 앞선 바텀시트 제안을 바꿀 핵심 근거

토스 디자인팀의 [‘이런 것도 컴포넌트로 만들어도 될까?’](https://toss.tech/article/tds-component-making)(2024-02-19)는 상단 셀렉터와 하단 시트 사이의 시선 이동을 문제로 삼았다. 누른 위치에서 열리는 메뉴를 실제 서비스에서 비교했고, 전체 지표에는 큰 변화가 없었으며 Android에서는 항목 클릭률이 10% 높았다고 보고했다. 특정 서비스의 10일 실험이므로 EduNote의 성과를 보장하는 수치가 아니다.

후속 [TDS 메뉴 개선 글](https://toss.tech/article/toss-design-system)(2024-03-05)은 긴 메뉴명, 많은 항목, 스크롤 가능성 인지, 큰 글자 및 보이스오버까지 다뤘다. 작은 팝오버로 바꾸는 것만으로 개선이 끝나는 것은 아니다.

[공개 BottomSheet 문서](https://tossmini-docs.toss.im/tds-mobile/hooks/OverlayExtension/use-bottom-sheet/)에는 시트와 하단 액션, 포커스 제한 등이 여전히 존재한다. 이는 바텀시트 폐기가 아니라 적합한 용도 선택을 뜻한다. 해당 문서는 컴포넌트 API이며 모든 서비스의 UX 결정 규칙은 아니다.

**수정된 제안:** 기간이 적으면 기간 버튼 근처 메뉴 또는 본문 상단에서 펼치는 선택 UI부터 비교한다. 많은 기간을 찾아야 한다면 전용 선택 화면도 비교한다. ‘짧으면 무조건 바텀시트’로 정하지 않는다.

## 4. 현재 share가 답해야 할 질문

현재 코드는 홈·기록·분석·오답·단어라는 5개 최상위 탭을 제공한다. 홈에는 최근 수업, 선생님 코멘트, 할 일, 기간 요약이 있다. 분석의 유형을 누르면 최대 82vh 시트 안에 오답 전문을 여러 개 보여준다.

이 구조에서 검증해야 할 가설은 다음과 같다. 아래 내용은 실제 학생 인터뷰 결과가 아닌 코드와 기존 QA에 근거한 판단이다.

1. **‘기록과 분석 중 어디를 봐야 하나’라는 분류 부담.** 학부모의 ‘지난번보다 나아졌나’라는 한 질문에 두 탭이 관련된다.
2. **오답과 단어가 서로 다른 종류의 최상위 메뉴다.** 오답은 상태, 단어는 학습 대상이다. 단어 오답 복습이 여러 진입점에 걸친다.
3. **같은 카드 규격이 여러 역할을 맡는다.** 한 줄 요약, 선생님 코멘트, 행동 목록, 그래프의 시각적 무게가 비슷해질 수 있다.
4. **긴 문제를 목록 단계부터 모두 읽어야 한다.** 유형별 오답을 찾는 행위와 실제 지문을 읽는 행위가 같은 시트에 섞인다.
5. **과거 조회와 지금 해야 할 일이 섞인다.** 기간 선택이 화면 전반에 적용되므로 ‘지금’이라는 제목을 붙이면 과거 기간에서 오해가 생긴다. 새로운 설계도 ‘선택 기간’과 ‘현재 미완료 과제’를 엄격히 구별해야 한다.

## 5. 레이아웃을 크게 바꾸는 세 가지 안

| 안 | 최상위 구조 | 장점 | 비용·위험 | 적합한 조건 |
|---|---|---|---|---|
| A. 기존 5탭 정돈 | 홈 / 기록 / 분석 / 오답 / 단어 | 기능 위치 변화가 작고 수정 범위가 적음 | 분류 중복과 탭 간 왕복이 남음 | 재설계 위험을 작게 제한할 때 |
| B. 3영역 과업 중심 — 우선 검증 추천 | 요약 / 복습 / 기록 | 확인·행동·과거 탐색이 명확해짐. 기록과 분석 연결, 오답과 단어의 공통 진입 가능 | 기존 사용자가 기능을 다시 찾아야 함. 분석 진입이 너무 깊어지지 않게 해야 함 | 학생과 학부모가 함께 사용하는 현재 share |
| C. 리포트 + 학습 모드 | 읽는 리포트 중심 홈 → 별도 복습 영역 | 문자 링크로 들어온 학부모에게 간단함. 리포트에 문맥이 남음 | 반복 학습하는 학생은 진입이 한 단계 늘 수 있음 | 학부모 열람 비중이 높고 학생 복습은 부차적일 때 |

현재는 B를 첫 프로토타입으로 추천한다. 최적이라고 확정하지 않는다. 빈번한 단어 복습 때문에 3탭이 오히려 더 느려질 수 있으므로 A와 비교해야 한다. C는 사용 비중 확인 전 전면 적용하지 않는다.

### B안 정보 구조

- **요약:** 이름·선택 기간 → 최근 수업 한 줄 해석 → 해당 수업 핵심 결과 → 가장 중요한 복습 진입 → 선생님 코멘트 → 변화 요약과 기록 연결.
- **복습:** 문제 / 단어를 눈에 보이는 세그먼트로 선택 → 미복습/전체, 회차 등 필요한 조건 → 짧은 항목 목록 → 해당 문항 읽기·해설·다시 풀기.
- **기록:** 회차별 / 변화·유형을 같은 영역의 내부 탭으로 제공 → 시험·단어·출결·과제 기록과 기간 분석. 분석은 깊숙한 설정 메뉴에 숨기지 않는다.

학생/학부모 역할을 입장 시 강제로 고르게 하지 않는다. 공유 링크는 사용자를 구별하지 못할 수 있다. 동일한 요약 안에 복습 진입을 제공하고 반복 이용은 탭으로 단축한다.

### 화면 구성 예시 — 문구와 숫자는 가상 데이터

```text
학생 이름                       9월 학습 ▾

최근 수업 · 9/24
독해는 나아졌고,
어휘는 한 번 더 확인해요

독해 8/10        단어 16/20        출석
직전 회차 +2개   직전 회차 -1개

[ 이 수업 오답 2문항 보기 ]
단어 복습 4개 →

선생님 코멘트
관계사 문제에서 근거 문장을 ...

선택 기간의 변화                 기록 보기 →
그래프는 여기서 한 가지 지표만

         요약       복습       기록
```

‘오답 보기’는 목록으로 이동하는 버튼이다. 실제 연습을 시작하는 위치에서만 ‘다시 풀기’를 사용한다. 예시의 점수 변화는 문항 총수가 같은 경우에만 적절하다. 실제 코드에서는 시험 규모가 다르면 기존 정답률/%p 기준을 유지한다. 실제 코멘트가 없다면 생성한 말로 선생님의 의견을 대체하지 않는다.

## 6. 오버레이 선택은 이 단계에서 다시 결정

| 과업 | 우선 비교할 UI | 확인할 실패 조건 |
|---|---|---|
| 기간 몇 개 중 하나 선택 | 버튼 근처 선택 메뉴 / 본문 내 펼침 | 긴 기간명 잘림, 아래 항목 발견 실패, 큰 글자에서 넘침 |
| 많은 과거 기간 검색 | 검색·정렬 가능한 전용 선택 화면 | 단순 선택에도 불필요한 단계 증가 |
| 시험/단어 전환 | 화면에 보이는 세그먼트 | 전환했는데 기존 조건이 남아 결과가 비는 상황 |
| 정답률·비교 기준 확인 | 수치 가까이 인라인 설명 | 설명이 본문을 밀어 위치를 잃는 상황 |
| 유형별 오답 탐색 | 복습 목록으로 이동하고 유형 조건 표시 | 원래 분석 위치와 선택 기간 복귀 실패 |
| 지문·해설 읽기 | 독립된 읽기 화면, 본문 단일 스크롤 | 뒤로가기 시 필터·목록 위치 소실 |
| 여러 필터를 한 번에 적용 | 바텀시트도 후보로 유지 | 적용/취소 의미 불명확, 키보드·스크롤 충돌 |
| 짧은 선택·확인 | 맥락에 따라 메뉴·다이얼로그·시트 | 시각적 거리, 오조작, 뒤 화면 포커스 노출 |

기간 ‘몇 개’의 수치 기준은 토스의 공식 규칙이 아니다. 실제 기간명 길이·폰트 확대 상태·화면 높이로 정한다. 3–5개와 20개 이상의 테스트 데이터부터 비교할 수 있다.

## 7. 시각적 변화 방향

- 요약 첫 문장을 가장 크게, 보조 지표와 날짜는 그보다 작게. 영역 구분은 여백과 구분선을 우선하고 모든 블록을 동일한 둥근 카드로 감싸지 않는다.
- 한 화면의 주요 행동을 쉽게 식별하도록 한다. 기존 선택·긍정 의미의 파랑 토큰은 유지 가능하지만, 링크와 큰 버튼을 모두 같은 강도로 강조하지 않는다.
- 문제 읽기 본문은 앞서 개선한 16px·보통 굵기·왼쪽 정렬을 유지한다. 마케팅 사이트의 거대한 제목과 화면 높이만큼의 여백을 학습 지문에 가져오지 않는다.
- 조회용 목록은 제목·상태·날짜를 먼저 보여준다. 내용 전문은 읽기 단계에서 제공한다. 오답 여부를 숨기거나 정답을 미리 노출하는 문제는 학습 모드별로 구별한다.
- 테마·설정은 학습 행동과 시각적으로 경쟁하지 않게 위치를 재검토한다. 토스 홈페이지의 햄버거 메뉴를 share의 주요 내비게이션으로 그대로 복제하지 않는다.
- 토스 브랜드의 블루·3D 이미지·글래스 효과는 제품 사용성이 검증됐다는 근거가 아니다. 학습 서비스 고유 목적과 현재 다크모드 토큰을 우선한다.

## 8. 다음 검증 순서

1. 실제 코드 변경 없이 A안과 B안의 모바일 클릭 프로토타입을 만든다. 동일한 가상 학습 데이터로 비교한다.
2. 학부모 과업: 최근 변화 파악, 선생님 의견 확인, 과거 수업 찾기. 학생 과업: 특정 유형 오답 찾기, 지문·해설 비교, 단어 복습 시작.
3. 과업 완료 여부·시간·잘못 들어간 탭·뒤로가기 횟수·기간 해석 오류를 기록한다. 클릭률 하나만으로 읽기 UX 개선을 주장하지 않는다.
4. 320/390/430px, 긴 기간명, 기간 다수, 기록 없음, 긴 지문, 자료 이미지, 글자 확대, 라이트/다크를 확인한다. 복습에서 분석으로 돌아올 때 필터·스크롤 복귀도 포함한다.
5. B안이 유리하면 정보 구조를 먼저 적용하고 시각적 스타일을 다듬는다. 바텀시트 라이브러리 교체부터 시작하지 않는다.

이번 조사에서 가장 강한 변화 제안은 ‘바텀시트 대신 다른 팝업’이 아니라, **기능별 5탭을 사용 목적별 영역으로 다시 묶고, 요약 → 찾기 → 읽기 → 행동의 깊이를 분명히 하는 것**이다. 이는 토스가 동일 구조를 사용한다는 주장이 아니라, 여러 공식 사이트에서 관찰한 패턴을 EduNote에 적용한 설계 가설이다.
