# Share 분석 인사이트 보완

사용자 요청: 분석 탭이 데이터를 나열하는 데 그치지 않고 학습 인사이트를 제공하도록 개선.

- 첫 제목을 최근 하락·반복 오답·소표본·이전 오답 등 확인된 상태에 맞춰 해석한다.
- 유형별 최근 두 실제 출제 회차와 직전 최대 두 회차의 정답 수/문항 수를 합산한다. 회차 정답률의 단순 평균이나 미출제 0% 보간은 사용하지 않는다.
- 최근 오답 유무, 표본 수, Wilson 오답률 점수와 반복 회차로 최대 3개 복습 순서를 제안하고 근거를 표시한다. 최근 오답이 없으면 누적 오답 복습을 제안한다.
- 추천 상위 두 유형의 기간 오답 합집합으로 집중도를 계산한다. 전체 오답이 2개 이하면 강조하지 않고, 비중이 50% 미만이면 여러 유형에 분산된 상태로 안내한다.
- 직전/최근 모두 3문항 이상이고 정답률이 15%p 이상 높아진 유형을 개선으로 소개한다. 강점은 최소 2회·5문항, 누적 및 최근 각 출제 회차 정답률 80% 이상 조건을 사용한다.
- 영역과 반복 패턴 입력도 선택 기간의 독해로 통일하고, 중복 태그를 제거한다. 다른 반의 같은 주차 번호는 날짜순 회차 ID별 키로 분리한다.
- 기존 전체 유형·회차 기록·영역 목록과 유형별 오답 드로어를 유지한다. 공용 Card·테마 토큰·모바일 디자인 사양을 따른다.
- DB/API 변경 없이 클라이언트 파생 계산으로 구현했다. 기존 작업 중 변경은 보존했다.

## 검증

- Node 24.19.0으로 `npm run check -- --maxWorkers=2 --minWorkers=1` 통과: 타입 오류 0, 린트 오류 0, 기존 경고 22, 55개 파일/702개 테스트 통과.
- 첫 검사에서 기존 영역 집계 테스트가 새 상단 결과와 같은 문자열을 찾아 실패했다. 해당 영역으로 조회를 한정해 영역 중복 집계 검증을 유지하고 전체 검사를 재실행했다.
- 375px 라이트 / 320px 다크, 긴 유형명 줄바꿈, 추천 유형 → 실제 오답 드로어 → 닫기, 소표본·만점·미분류·빈 기록 전환 확인. 가로 넘침 및 브라우저 콘솔 오류 없음.
- 가상 입력만 사용한 재현 미리보기: `node scripts/preview-share-analysis.mjs` (127.0.0.1:3108).
- 검증 이미지: `docs/qa/share-analysis/insights-light.jpg`.
- 실제 학생 데이터와 운영 환경의 E2E 검증은 수행하지 않았다. LLM 호출, 커밋, 푸시, 배포는 하지 않았다.

## 그래프·가독성 보완

후속 요청: UI가 복잡해 보이며 그래프·시각화가 효과적일지 검토.

- 기본 화면을 짧은 해석과 3개 카드(유형별 정답률 흐름 / 복습 순서 / 오답 범위)로 줄였다. 반복된 설명을 제거하고 전체 유형·영역·회차 비교·계산 기준은 기본 접힘으로 보존했다.
- 복습·개선·강점 중 최대 3개 유형을 선택해 한 유형의 실제 출제 흐름만 표시한다. 최근 최대 6점, 0–100% 고정 축, 날짜 끝점과 출제 회차 순 라벨을 사용한다. 한 회차는 점 하나이며, 미출제는 0%로 채우지 않는다.
- 그래프의 개별 회차 정답률과 최근 최대 두 회차 합산 정답률을 구분했다. 모든 회차 수치는 별도 펼침에 유지하고 소표본 회차가 있으면 안내한다. 회차별 난도·문항 수 차이도 짧게 명시했다.
- 오답 범위는 추천 두 유형의 합집합과 그 외를 나눈 막대로 표시한다. 문항 수는 막대 밖에 표기하며 그 외 0문항도 유지한다.
- 긴 유형명은 선택지에서 줄이고 본문·접근성 이름에서 전체 이름을 유지한다. 320px에서도 세 선택지가 균등한 폭에 들어가며 최소 44px 높이를 확보했다. 오답 버튼의 표시 문구와 접근성 이름을 일치시켰다.
- 디자인 요약과 handoff README에 이번 구조를 우선 사양으로 반영했다.

## 많은 유형의 보완 우선순위·라이브러리 차트

후속 요청: 유형이 많아도 학생의 약점과 집중 보완 대상을 명확하게 표시하며 차트는 깔끔한 라이브러리를 활용.

- 복습 추천을 그래프 앞으로 옮겼다. 충분한 최근 기록에서 보완할 유형이 있으면 그 유형만 최대 3개 추천하며 안정적·기록 부족 유형으로 추천 개수를 채우지 않는다. 추천이 적으면 그 개수대로 표시한다.
- 유형별 최근 두 실제 출제의 합산을 우선 보완 / 복습 권장 / 안정적 / 기록 부족으로 분류하고 개수를 집계한다. 최근 2문항 이하는 판단을 보류하고, 충분한 기록의 60%·80% 경계와 15%p 하락 기준은 반올림 전 비율로 판정한다. 최근 80% 이상은 예전 오답이나 하락 때문에 약점으로 강조하지 않는다. 표기 반올림과 분류 기준을 안내한다.
- 오답 범위는 추천 카드의 짧은 보조 정보로 통합했다. 전체 유형은 기본 접힘 안에서 이름 검색·상태 필터·분류별 간결한 행으로 조회하며 기본 8개 이후도 모두 접근할 수 있다. 기간 변경 시 펼침·검색·필터를 초기화한다.
- 설치된 Recharts 3.8.0으로 선 그래프를 교체했다. 직접 SVG 좌표·path·circle을 계산하는 코드를 제거하고 반응형 크기·축·선·최신 점·툴팁을 라이브러리로 처리한다. 4개 이상 유형은 상태별 전체 선택 목록에서 한 유형씩 표시한다. 최대 6회·고정 0–100%·분모·전체 기록·소표본 안내를 유지한다.
- 분석 탭을 열 때 관련 모듈을 불러오도록 변경했다. 패키지를 추가하거나 버전을 변경하지 않았다. 접힌 회차 비교의 작은 수작업 그래프도 제거해 실제 숫자 비교로 유지했다.
- 가상 24개 유형(우선 보완 4 / 복습 권장 2 / 안정적 10 / 기록 부족 8)으로 추천 제한, 전체 검색, 상태별 필터, 추천 밖 유형의 차트 조회와 실제 오답 이동을 검증했다. 375px 라이트와 320px 다크, 긴 유형명·한 문항·만점·빈 기록·26회 기록도 확인했으며 가로 넘침과 브라우저 경고·오류가 없다. 실제 학생 데이터의 운영 E2E 검증은 추가하지 않았다.
- 최종 `npm run check -- --maxWorkers=2 --minWorkers=1` 통과: 타입·린트 오류 0, 기존 린트 경고 22, 56개 파일/728개 테스트 통과. 분석 로직 23개·분석 UI 16개·차트 12개 테스트 포함. 대상 UI 검사 중 일시적 RPC 시간 초과는 재실행에서 재현되지 않았고 최종 전체 검사도 통과했다.
- `git diff --check` 통과. 미리보기 이미지: `docs/qa/share-analysis/many-types-light.jpg`.
- DB/API 변경, 유료 LLM 호출, 커밋·푸시·배포는 추가하지 않았다.

## 분석 탭 전체 시안과 조작 정리

후속 요청: 분석 탭 전체 시안을 직접 보고 조작할 수 있게 제공하며 UI를 더 간결하게 정리.

- 추천 행은 유형명·최근 합산 정답률·최근 문항 중 오답 수로 줄였다. 헤드라인 아래·추천·차트에서 반복하던 상세 근거를 정리했다. 오답 집중도는 짧은 문항 수 요약을 펼쳐 확인한다.
- 차트의 최근 합산 정답률·실제 정답/문항 수·직전 묶음 대비 변화량을 그래프 위에 모았다. 회차별 그래프와 합산값을 구분하며 많은 유형 선택의 일반 상태 중복을 없앴다.
- 전체 유형 카드에 네 상태의 개수를 기본 노출한다. 상태를 누르면 해당 유형 목록이 열리고 검색·더 보기를 초기화한다. 검색과 네이티브 상태 필터를 함께 적용할 수 있고 전체 24개도 조회할 수 있다. 목록 접기는 검색 위에 둔다.
- 긴 전체 분석 펼침을 제거하고 회차별 변화·영역별 요약·분석 기준과 추천 이유를 각각 독립적으로 펼친다. 유형별 실제 오답 이동·모든 수치·분류 계산은 보존했다.
- 실제 분석 컴포넌트에 가상 학생·24개 유형을 연결한 전체 미리보기를 제공한다. 검토 도구는 보고서 밖에 두며 샘플/테마 URL과 도구 없는 캡처 모드를 지원한다. 분석 탭만 렌더링한다.
- 375px 라이트 / 320px 다크에서 전체 흐름과 가로 넘침 없음, 상태 직접 필터, 검색한 장문 유형의 실제 오답 드로어, 상태 전환 시 검색 초기화, 브라우저 경고·오류 없음을 확인했다. 전체 기본 이미지 `docs/qa/share-analysis/analysis-full-mock-light.jpg`, 유형 목록 펼친 이미지 `docs/qa/share-analysis/analysis-full-mock-types.jpg`를 저장했다.
- 계산에 대한 후속 질문에는 약점 분류가 선택 기간 안의 최근 두 실제 출제 회차 전체 문항(정답과 오답 포함), 누적 오답 수·반복 회차는 선택 기간 전체, 변화 비교는 그 이전 최대 두 실제 출제 회차임을 안내했다. 이번 UI 변경에서 계산 로직은 바꾸지 않았다.
- 최종 `npm run check -- --maxWorkers=2 --minWorkers=1` 통과: 타입·린트 오류 0, 기존 린트 경고 22, 56개 파일/730개 테스트 통과. 분석 UI 18개·차트 12개 테스트를 포함한다. 제한된 파일 접근에서 esbuild의 상위 패키지 설정 읽기가 막힌 첫 실행은, 승인된 검증 실행에서 정상 완료했다.
- DB/API 변경, 유료 LLM 호출, 커밋·푸시·배포는 하지 않았다.

## 누적 분류와 최근 흐름의 표본 보완

후속 요청: 최근 두 번의 출제만으로 약점을 판단하기에는 기록이 너무 적다는 피드백. 승인된 화면 구조를 유지하며 계산 기준과 수치 설명을 수정했다.

- 보완 분류와 목록 정답률은 선택 기간 안의 모든 실제 출제 문항(정답·오답 포함)을 합산한다. 유형별 3회 이상·10문항 이상일 때 60%·80% 경계로 분류하며, 부족하면 판정을 보류한다. 이는 복습 안내를 위한 제품 기준이며 통계적 확신을 보장하는 기준은 아니다.
- 최근 흐름은 최대 네 실제 출제 회차를 합산하고, 그 앞의 최대 네 회차와 비교한다. 양쪽 각각 3회 이상·10문항 이상인 경우에만 변화량을 표시한다. 회차별 정답률 그래프는 실제 최근 여섯 점을 유지한다.
- 충분한 최근 기록에서 안정적으로 회복한 유형은 보완 추천에서 제외한다. 기간 누적은 안정적이어도 최근 기록이 우선 보완에 해당하면 최근 확인 대상으로 추천한다. 기간 분류와 최근 상태의 범위를 문구로 구분한다.
- 추천·전체 목록에는 기간 누적 정답률을 표시하며, 유형 선택과 전체 분류에도 누적 기준을 명시했다. 별도 회차 비교는 참고 수치로 표시하고 두 번의 결과만으로 상승·하락을 단정하는 강조를 제거했다.
- 분석 로직 31개·분석 UI 19개·차트 16개 테스트로 표본 경계, 가중 합산, 실제 출제 회차, 회복·최근 주의, 추천 제한, 화면 표시를 확인했다. 최종 `npm run check -- --maxWorkers=2 --minWorkers=1` 통과: 타입·린트 오류 0, 기존 린트 경고 22, 56개 파일/743개 테스트 통과.

## 한눈에 읽는 분석 시안

후속 요청: 학생의 약점과 집중 보완 대상을 더 직관적으로 파악할 수 있게 적합한 그래프를 판단해 분석 탭 시안을 제공.

- 전체 유형의 네 상태 개수를 상단으로 올리고 별도 카드를 제거했다. 숫자는 유형 수이며 기간 누적 범위를 명시한다. 상태 직접 선택·검색·필터·여덟 개 이후 더 보기·접기·기간 변경 초기화를 보존한다.
- 보완 유형은 최대 세 행의 Recharts 가로 막대로 비교한다. 길수록 오답이 많은 방향으로 누적 오답률을 표시하며, 실제 오답 수/문항 수로 계산한 0–100% 공통 범위를 사용한다. 표시만 반올림한다. 동률에 인위적인 순위 번호를 붙이지 않는다.
- 추천 행에 유형명·오답률·문항 분모·짧은 반복 근거·명시적 오답 보기 액션을 모았다. 부족한 기록은 중립색·판정 보류, 최근 주의는 최근 묶음 정답률, 최근 회복은 이전 오답 확인으로 구분한다. 기존 전체 유형 목록은 기간 정답률을 유지한다.
- 충분한 누적 보완 대상의 첫 해석은 실제 유형명과 복습 제안으로 표시한다. 최근 주의·회복·기록 부족·만점·빈 기록의 해석은 해당 상황을 유지한다.
- 단일 유형의 최근 선그래프는 기본 접힌 상세로 내리고, 펼칠 때만 렌더링한다. 모든 유형 선택·실제 최근 최대 여섯 점·최근/직전 합산과 표본 조건·전체 수치·오답 이동을 보존한다. 회차·영역·계산 근거도 독립 펼침이다.
- 기존 동률 24개 가상 기록을 보존하고, 비교에 적합한 서로 다른 수치의 24개 사례와 충분한 최근 주의/회복 사례를 미리보기에 추가했다. 실제 학생 기록이나 분석 분류 계산은 바꾸지 않았다.
- 첫 전체 검사에서 접힌 차트의 노출을 조회하던 테스트 두 개가 실패했다. 최근 차트의 초기 렌더링을 미뤄 접힘·접근성·초기 비용을 함께 정리했고, 최종 `npm run check -- --maxWorkers=2 --minWorkers=1` 통과: 타입·린트 오류 0, 기존 린트 경고 22, 57개 파일/749개 테스트 통과. 비교 차트 6개·분석 UI 19개·최근 차트 16개 테스트를 포함한다.
- 375px 라이트/320px 다크, 추천에서 실제 15개 오답 드로어로 이동·닫기, 상태별 목록·검색과 상태 재선택, 최근 차트 펼침과 실제 선 렌더링, 최근 주의·회복·한 문항 판정 보류·만점·긴 이름을 확인했다. 가로 넘침과 브라우저 경고·오류 없음. 실제 학생 데이터의 운영 E2E 검증은 추가하지 않았다.

## 영역 요약과 시안 선택 정리

후속 요청: 영역별 요약에 레이더가 더 적합한지 판단하고, 우측 상단 기록 선택의 항목과 문구를 필요한 내용만 남겨 정리.

- 영역 수는 기록과 태그에 따라 1개부터 달라지고, 영역별 문항 수 역시 다르다. 모바일에서 영역명·수치·분모를 직접 비교하는 목적에 맞춰 중립 가로 막대를 유지한다. 레이더를 추가하지 않았다.
- 영역 요약에 선택 기간 누적 정답률 범위를 명시하고, 실제 정답/문항 수를 유지했다. 긴 포함 유형 목록은 ‘포함된 유형 N개’에서 펼쳐 확인한다. 막대 대비를 높였으며 임의의 영역 표본 판정이나 능력 분류를 추가하지 않았다.
- 상단 선택 이름을 ‘학습 상황’으로 바꾸고, 기본 분석·기록 부족·최근 오답 증가·최근 회복·모두 정답 다섯 사례만 제공한다. 중복/검증용 사례와 불필요한 가상 데이터 정의를 제거하고 안내 문구를 정리했다.
- 모바일 검증 중 선택값이 좁아지는 배치를 발견해 도구를 별도 줄에 배치했다. 데스크톱 우측 상단 배치는 유지하며 선택·테마 버튼은 최소 44px다. 프리뷰 시작 안내 URL도 현재 기본 사례로 갱신했다.
- 영역 다중 태그 중복 집계 테스트에 범위 설명과 포함 유형 펼침 검증을 추가했다. 최종 `npm run check -- --maxWorkers=2 --minWorkers=1` 통과: 타입·린트 오류 0, 기존 린트 경고 22, 57개 파일/749개 테스트 통과.
- 1024px 데스크톱, 375px 라이트/320px 다크에서 다섯 선택 문구, 사례와 테마 전환, 긴 선택값 표시, 영역 수치·포함 유형 펼침, 가로 넘침과 브라우저 오류/경고 없음을 확인했다. 사용자가 선택했던 회복 사례·라이트 화면으로 복원하고 뷰포트 제한을 해제했다.
