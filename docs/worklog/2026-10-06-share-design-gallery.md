# Share 디자인 이력 화면

요청: 개발자 도구에서 여러 Share 시안을 선택하고 실제 화면처럼 전체 흐름을 확인.

- `/dev`에 ‘Share 디자인’ 탭을 추가하고 `/dev/share-design`에도 같은 갤러리를 연결했다. 기존 320px 높이의 단순 Share 프리뷰는 전용 화면으로 통합했다.
- 목록 중심(9/29), 추이 중심(10/1), 현재 보완 중심(10/1)을 등록했다. 과거 버전은 분석 레이아웃을 재현하고 현재 누적 계산을 동일하게 적용한다. 현재 시안은 실제 `AnalysisTab`을 사용한다.
- 운영 화면의 셸을 `ShareReport`로 추출해 헤더·기간 선택·고정 5탭·홈·기록·오답·단어·오답 드로어·개인 복습을 그대로 재사용한다. 프로덕션 리포트는 기존 Share API와 재시험 경로를 유지한다.
- 링크/토큰 입력으로 현재 앱의 학생 데이터를 조회할 수 있다. 미리보기 기록은 학생·독해 지문·5선지·해설·단어 예문·성적·출결·클리닉·숙제·코멘트를 포함한다. 3개 기간과 5개 학습 상황을 제공한다. 미리보기 재시험에는 실제 학생 링크를 사용하도록 안내한다.
- iframe 안에서 고른 기간·탭은 출처/프레임 window/형식을 검증한 메시지로 갤러리에 전달한다. 탐색 중 iframe을 재로딩하지 않으며, 시안·테마 변경과 ‘화면만 열기’에 현재 기간·탭을 보존한다.
- 320/375/430px와 라이트/다크를 선택한다. 고정 탭·시트는 iframe의 화면을 기준으로 동작한다. 테마 저장 키를 분리해 일반 Share 화면의 설정을 바꾸지 않는다.
- 전체 기간의 다른 기간 오답 행은 해당 기간으로 이동한 후 올바른 독해/단어와 회차를 연다. 조회 중에는 셸 상태를 보존하되 이전 기간의 수치를 숨긴다. 기존 오답 복습 CTA의 회색 배경/흰 글자 대비도 공통 토큰으로 바로잡았다.
- 새 시안은 `share-design-registry.ts`와 frame의 분석 렌더러에 추가한다. 갤러리 선택이 일반 학생 공유 화면의 디자인을 바꾸지는 않는다.

## 검증

- 개별 검사: 이력 UI 9개, 갤러리 메시지·기간/탭 보존·실제 링크 입력 26개, 링크/프레임 및 기록 정합성 40개 통과. ShareReport에 5탭·드로어·기간 전환·전체기간 오답 이동·로딩 회귀 테스트를 추가했다.
- 브라우저: 3개 시안, 320px 다크/375px 라이트, 실제 5탭 셸과 오답 원문·해설, 기간 시트 키보드 조작, 12회·288문항 → 2회·48문항 재계산, 9월·기록 선택 후 다른 시안에서도 동일 선택 유지, 현재 맥락의 별도 화면 링크를 확인했다. 확인한 화면의 런타임 오류/경고는 없었다.
- 최종 전체 `npm run check` 결과는 아래에 기록한다. 첫 병렬 검사에서는 803/804 통과했고 통합 5탭 테스트가 Next 첫 컴파일 부하와 겹쳐 시간 제한에 걸렸다. 기본 입력을 2회로 줄이고 해당 통합 테스트에만 10초 제한을 적용해 단독 전체 검사를 다시 실행했다.
- 실제 학생 데이터·재시험 제출의 운영 E2E는 수행하지 않았다. DB/스키마/API 변경, 유료 LLM 실행, 커밋·푸시·배포는 하지 않았다.

## 2026-10-07 인계 시점

- 사용자가 미완료 작업을 새 브랜치로 푸시해 다른 PC에서 이어가도록 요청했다. 현재 폴더의 미커밋 변경과 인계 문서를 `codex/wip-handoff-2026-10-07`에 WIP 체크포인트로 보존한다. 기능 완료 또는 전체 검증 통과를 뜻하지 않는다.
- 마지막 전체 `npm run check -- --maxWorkers=1 --minWorkers=1`은 타입/린트를 지나 테스트에서 실패했다. 65개 파일 중 54개 통과·11개 실패, 실행된 778개 테스트 중 777개 통과·1개 실패와 unhandled error 1개다. 신규 Share 갤러리 테스트의 과거 통과 기록과 현재 전체 실패를 구분한다.
- LLM 리팩터링 관련 `server-only` import/mock suite 오류, 기존 독해 복습 흐름의 5초 timeout, Vitest worker RPC timeout이 남았다. 약 74,222초의 비정상 실행 시간은 PC 정지 영향이 의심되지만 원인을 확정하지 않았다.
- 다른 PC의 환경 준비, 대화 결정사항과 남은 작업은 `docs/worklog/2026-10-07-pc-handoff.md`에 정리했다. 배포/운영 반영은 하지 않았다.
