# 2026-10-19 — 복합 저장 트랜잭션 전환

## 이번 전환 범위

통합 작업 폴더의 기존 `withTeacherTransaction` / `edunote_app` 계층을 확장했다.
Auth, 조회, Storage는 기존 연결을 유지한다. 운영·개발 DB에는 SQL을 적용하지 않았다.

- 단어 원본 교체: 삭제·단어/variant 삽입·시험 문항/기존 답안 복구·점수/원본 메타데이터 갱신을 한 번에 저장한다. AI 재채점은 DB 변경 전에 완료한다.
- 단어시험 생성: 채점 답안 존재 검사를 잠금 안에서 다시 수행하고, 기존 시험 비활성화·시험/문항 생성·문항 수 갱신을 함께 저장한다. 실패 시 수동 복구 쿼리 대신 전체 rollback한다.
- 독해 일괄 채점: 코드/AI 평가 뒤 점수·답안·AI 결과·합계를 같은 연결에서 저장한다. AI 실패 시 기존 응답 규약대로 코드 채점 결과를 저장하고 AI 실패를 알린다.
- 교사 확정, 정답/태그 변경 후 재채점, 단어 답안 수정/재채점: 답안과 점수 합계를 함께 저장한다.
- 단어 사진 채점: OCR 뒤 단어 보강·답안·점수·문항 수·사진 경로를 함께 저장한다. Storage는 별도 고유 경로에 먼저 업로드하며 DB 실패 시 새 객체 정리를 시도한다. Storage 자체는 PostgreSQL rollback 대상이 아니다.
- 모의고사: 시험+기본 문항 생성, 답안+점수 저장, OMR 결과 저장, 문항/메타데이터 변경+전체 재채점, 성적표 snapshot+게시 상태 갱신을 각각 원자적으로 저장한다. 성적표 일괄 발행은 요청 전체가 하나의 transaction이다.
- 학생: 생성+반 등록, 재등록, 등록일 수정, 반 퇴원/전체 퇴원+보충수업 배정 종료, 정보 수정/삭제를 서버 transaction으로 옮겼다.

## 잠금과 권한

주차 작업은 반 → 주차 → 관련 문항/단어/시험/점수/답안 순서로 잠근다. 학생 등록 변경도 반 → 학생 순서를 따른다. 전체 퇴원은 반 ID 정렬 순서로 잠근다.
준비 단계의 자료 fingerprint를 저장 직전에 다시 비교한다. AI/OCR 중 같은 학생의 답안, 시험 구성, 정답 등이 변경되면 409를 반환한다.
다른 학생의 동시 채점과 파생 문항 수 갱신은 별도 학생의 fingerprint를 무효화하지 않는다. 원본 교체는 전체 주차 답안을 비교한다.
기존 HTTP writer의 변경도 잠근 행과 FK 부모 잠금을 기다리지만, 남은 복합 HTTP writer 자체가 원자적으로 바뀌었다는 뜻은 아니다.

기존 RLS 정책·함수·트리거는 제거하지 않았다. 추가 정책은 `edunote_app`에만 적용된다.
개발의 allow-all이나 운영의 공개 SELECT 정책이 있어도 신규 restrictive 정책이 승인된 교사/소유권과 답안의 주차 연결을 제한한다.
기존 `clinic_enrollment_owner` 정책이 참조하는 `clinic_slot` 조회 권한도 포함했다.
새 SQL은 다른 역할의 권한을 바꾸거나 BYPASSRLS/역할 상속을 부여하지 않는다.

## 적용 순서

1. 개발·운영 SQL Editor에 `supabase/migrations/20261019000002_expand_transaction_writes.sql`을 각각 적용한다. 기존 `20260929101449_server_transaction_role.sql` 및 환경별 전용 역할 설정이 선행되어야 한다.
2. 개발 환경에서 시험 생성/교체, 채점, 학생 등록/퇴원과 타 교사 접근 차단을 확인한다.
3. 검증한 앱을 배포한다. 권한 준비 전에는 이 코드를 배포하지 않는다. 실패 시 HTTP 순차 저장으로 fallback하지 않는다.

이전 정리 요청의 `20261019000001_drop_unused_generate_weeks.sql`은 별도다. 이번 전환 SQL이 유효한 기존 함수를 삭제하지 않는다.

## 검증

- `tests/unit/compound-transactions.test.ts`: PostgreSQL(PGlite)에 합성 스키마와 실제 권한 SQL을 적용한다. 중간 실패 rollback, stale AI/OCR 차단, 다른 학생의 동시 저장 독립성, 타 교사 연결 차단, 무효 문항 집계, 배열/JSON 저장, 성적표 snapshot 개인정보 제한을 검증한다.
- 마지막 테스트에서는 운영에서 읽은 실제 정책 표현식을 `tests/fixtures/production-compound-policies.sql`로 재현해 등록·퇴원·문항 수정·모의고사 저장/발행을 검사한다. 운영 업무 데이터는 fixture에 포함하지 않는다.
- `tests/unit/grade-transaction-route.test.ts`: AI 실행이 저장 transaction 앞에 있고 단 한 번의 저장 계획으로 점수/답안이 전달되는지, AI 실패와 409 응답을 검사한다. 실제 AI는 호출하지 않는다.
- hosted DB에 대해서는 시스템 카탈로그·정책·기존 역할의 상속 권한만 읽었다. 실제 Supavisor 접속/운영 저장은 이번 검증에 포함하지 않는다.

## 남은 전환 범위

이번 작업으로 앱 전체 저장이 전환된 것은 아니다. 다음 경로는 별도 서비스화와 실패/권한 테스트가 남아 있다.

1. `week-reading-import.ts` 및 PDF 파싱·문항 가져오기: 문항/선지/태그 교체·답안 재채점·파일 경로 갱신.
2. 문제은행·어휘 컬렉션 및 일반 성적표 복합 저장.
3. 보충수업 편성·출결·반 정보 수정, 개념/태그, 메모·프로필 등 단일 저장 경로.
4. 공유 토큰으로 호출하는 재시험: 교사 Auth 세션이 없으므로 `withTeacherTransaction`을 그대로 적용하지 않고 토큰 권한에 맞는 별도 경계를 설계해야 한다.
5. 문자·Auth 가입·Storage 등 외부 부작용: PostgreSQL transaction 안에서 기다리지 않는다. 필요한 곳은 outbox/멱등성/실패 복구로 별도 보장한다.

로컬 기본 작업 폴더의 미커밋 PDF 워커 작업은 이번 통합 코드에 포함하거나 덮어쓰지 않았다. 커밋·푸시·배포하지 않았다.
