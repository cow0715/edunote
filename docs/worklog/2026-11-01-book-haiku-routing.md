# 교재 매핑·보완 Haiku 전환 / Sonnet 원본 대조 유지

사용자 승인 범위: 교재의 매핑·풀이·어휘 보완을 Haiku로 변경하고 최종 원본 대조는 Sonnet 유지. 두 모델의 관측된 JSON 형식 오류 수정 및 기존 응답 재사용. 자동 재개·유료 호출 금지. 후속 메시지에서 비용 정산 SQL 개발·운영 직접 적용도 승인했다. 커밋·푸시·배포는 요청하지 않았다.

## 처리 경로

- `book.mapSource`와 `book.enrichMaterial` 신규 요청만 `claude-haiku-5-5`.
- `book.auditSource`(원본 이미지 대조·부분 복구·수정 후 전체 재검사)는 `claude-sonnet-5-5` 유지.
- 코드로 확정되는 형식별 매핑은 그대로 쓰고, 기존 검증 원문·완료 문항은 다시 매핑하지 않는다.
- 기출·주차별·채점의 모델·요청·Batch/동기 처리 유지. 기존 비교재 체크포인트 키도 기존 교재 카탈로그를 투영해 바이트 단위로 유지한다.
- 검증 및 보완 기록은 실제 응답 모델을 기록한다. Sonnet 보완 응답을 재사용하면 Haiku로 바꿔 적지 않는다. 새 혼합 모델 완료 증명에는 실제 보완 모델을 포함한다. 매핑 모델 기록도 재시작을 거쳐 유지한다.

## 기존 응답 및 형식 복구

- 이전 `routing-v1:4aed6b2450f3`의 Sonnet 요청 식별자를 원본·좌표·문항·프롬프트가 정확히 같은 경우에만 조회한다. 현재 Haiku 설정으로 옛 키를 잘못 계산하지 않는다.
- 기존 일반/레이아웃/결합 검증·부분 복구 프롬프트 바이트와 키는 호환 전용 상수로 유지한다. 새로운 지시문은 새 요청에만 쓴다.
- pass/unreadable의 누락된 `repair:null`만 채운다. 명시된 수정 객체를 없애거나 불일치 판정을 pass로 바꾸지 않는다.
- refs 수정에 덧붙은 `pages`는 검증된 원본 창 안의 유효한 배열일 때만 중복 메타데이터로 정리한다. 원문 범위·소유권·대상·원본 이미지·후보 해시·패치 앵커·허용 필드는 계속 검사한다.
- 프롬프트의 첫 정상 JSON 예시에도 repair:null을 넣고, refs/patch/text 각각의 허용 키를 명시한다. 순서 문항의 제시문 배치와 공유 소재를 취향에 따라 옮기거나 지우지 않게 명시한다.
- 과거 형식 오류만으로 끝난 검증은 기존 원시 응답을 다시 읽어 판정한다. 원시 응답이 없으면 재시작해도 유료 재요청을 막는 replayOnly 상태를 유지한다. 원본 수정 후 새 전체 대조와 기존 2회 복구 상한은 그대로다.
- 복구 정책 버전은 3. 변경된 정책으로 명시적 재시도를 허용할 수 있게 했으나, 작업 상태나 예약 재개를 바꾸지는 않았다.
