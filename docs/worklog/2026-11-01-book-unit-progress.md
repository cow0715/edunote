# 교재 문항 진행 저장과 재과금 차단

목표는 기존 네 교재의 유료 응답과 검증 결과를 보존하면서 남은 단계만 완료하는 것이다. 기출·주차별 경로와 원본 이미지 대조 기준은 유지한다.

## 진행 상태

- 원본 PDF 해시와 문항 묶음 manifest 해시를 기준으로 매핑, 원본 검증·수정, 검증 완료 원문, 풀이·어휘 완료 결과를 각각 저장한다. 공유 지문에는 모든 문항 key를 연결한다.
- 매핑 수정 시도 횟수, 거절된 후보와 오류를 저장한다. 배치 대기나 워커 종료가 시도 횟수를 초기화하지 않는다.
- 이미지 검증은 판정과 수정 후보·수정 이력을 저장한다. 수정 후에는 전체 원본 이미지에 대한 새 검증을 요구한다. 최대 두 번 수정하며, 확정된 보류 상태도 재시작 후 유지한다.
- 검증된 원문과 완성 결과는 교체하지 않는다. 완료 후 문항 테이블 staging 전 워커가 종료되어도 결과를 재사용한다.
- JSONB 키 순서 변경이 기존 요청·수정 후보 해시를 바꾸지 않도록 진행 payload를 JSON 문자열과 해시로 보존한다.

## 중복 요청

- 기존 정확한 LLM 요청 키는 변경하지 않는다. 추가한 `bookOperation`은 공급사 전송 및 기존 요청 키에서 제외한다.
- 별도로 문서·문항·작업 종류·원문/후보 근거를 해시한다. 프롬프트·모델 라우팅·출력 상한 변경은 이 식별자를 바꾸지 않는다. 실제 근거 변경이나 수정 단계는 구별한다.
- 이미 받은 정확한 응답은 원래 체크포인트를 가리키는 별칭으로 연결한다. 별칭은 정확도 승인으로 사용하지 않는다. 파싱과 원본 이미지 검증은 그대로 수행한다.
- 진행 중·접수 여부 불명·성공 응답 유실 상태에서 새 키로 재접수하지 않는다. 확실한 일시적 실패는 같은 요청 키로만 기존 3회 접수 한도 안에서 재시도한다.
- DB에서도 문서 잠금 후 기존 요청과 별칭을 검사한다. 다른 작업 ID나 동시 요청으로 중복 방지와 기존 예산·호출 상한을 우회하지 못한다.

## SQL과 배포

`supabase/migrations/20261101102036_book_unit_progress_and_request_guard.sql`을 개발·운영에 적용한 다음 워커를 배포해야 한다. 기존 체크포인트 테이블을 사용하며 신규 원문 테이블이나 예산 변경은 없다.

`book_pdf_save_unit_progress`는 실행 중 교재 작업의 유효한 lease와 실제 문항을 검사하고 `book-unit-stage:v1:` 범위만 갱신한다. 원래 유료 응답 체크포인트 저장 RPC는 변경하지 않는다. 모든 신규 RPC는 service_role 전용이다.

SQL의 `unit_guard_version=1`을 확인하지 못하면 새 교재 접수를 중지한다. SQL 적용·코드 배포 자체는 작업 재개를 의미하지 않는다. 기존 네 작업의 보류·예산 확인, 필요 시 묶음/형식 사전 검사 연결은 재개 전에 별도로 확인한다.

구현 단계에서는 운영 데이터 변경, 작업 재개, 모델 호출, 예산 조정, 커밋·배포를 수행하지 않았다.

## 검증 결과

- 최종 `npm run check -- --maxWorkers=2`: 204개 파일, 1,746개 테스트 통과. 타입·린트 오류 0, 기존 경고 21개 유지.
- `npm run build:worker` 통과.
- 네 PDF의 기존 유료 응답 1,577개를 운영 응답 해시와 대조하고, 운영에 이미 복구한 원본 검증 체크포인트 124묶음을 포함해 오프라인으로 처음 실행/재시작을 재생했다. 두 실행의 다음 요청 키와 진행 결과가 파일별로 일치했다. 네트워크 시도는 0건이다.
- 원본 검증 복구량: 영독 상 36, 영독 하 32, 수완 유형 33, 수완 실전 23묶음. 풀이·어휘까지 완료된 문항은 각각 11/35/4/2개로 총 52개를 유지했다. 검증 대기를 완료로 승격하지 않았다.
- 로컬 PostgreSQL에서 동시 접수, 다른 작업 ID를 통한 중복, 성공 응답 유실, 일시적 실패 3회 제한, lease·권한, 원래 유료 체크포인트 불변, 승인된 단계 교체 금지, 마이그레이션 재적용을 검증했다.
- 운영 읽기 확인: 네 작업은 failed/resume_after=null, 각 상한 $5, 누적 지출 $30.134968, 처리 큐 PAUSED. 새 SQL은 아직 개발·운영에 적용하지 않았다.

상세 재생 결과는 로컬 ignored 파일 `tmp/pdfs/unit-progress-seeded-report.json`, 최종 검사 로그는 `tmp/book-unit-progress-final-check.log`에 있다.

## 운영 반영

후속 사용자 요청에 따라 SQL을 개발·운영 DB 모두에 적용했다. 신규 함수 5개의 정의가 두 DB에서 일치하고 invoker/service_role 전용 권한을 확인했다. 기존 작업·예산·비용·복구 데이터·체크포인트는 적용 전후 동일하다.

운영 Vercel은 별도 CLI 배포된 등록·처리 UI(`dpl_H5Tnc9QKx2mrToZq5T5cAYG7CnXT`)를 사용 중이었다. 새 Git 배포가 이 화면을 되돌리지 않도록 운영 소스 SHA1과 일치하는 다섯 파일 및 검증된 관련 테스트를 함께 보존한다. 새로운 화면 설계 변경은 추가하지 않는다.

자동 처리 재개·유료 호출·예산 상한 변경은 이번 배포에도 포함하지 않는다.
