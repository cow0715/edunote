# 이번 세션 변경의 main 통합

사용자가 테스트 후 main 병합·푸시를 명시적으로 요청했다.

기준 원격 main은 `a562a03aaaa26d570d9a162abe5ba4784324332a`이며, 현재 운영 배포 소스인 `703024cf324a35b93025c9b5b8e12f1fa4b4ef9e`의 조상이다. UI만 따로 적용하면 main 재배포에서 운영 중인 과금 방지 코드가 빠질 수 있으므로 다음 기존 운영 커밋을 이력 변경 없이 함께 보존했다.

- e164e3cd6: Batch 비용 상한과 기존 응답 재사용
- 2105fe71e: 교재 등록 형식·묶음 예산 제어
- a6efde246: 원본 교정 후 재검증
- 19bfc9726: 이번 세션에서 배포한 등록·처리 UI와 테스트
- 703024cf3: 이미 운영 중인 문항 진행률·중복 과금 방지

자료 목록은 공통 기출 카드 형식, 등록·처리는 실제 저장 수량·미저장 사유·원본·복구 비용을 보여주는 최종 상태다. 영독(하) 120문항 복구 기록도 함께 보존한다.

기본 작업 폴더와 다른 작업 브랜치의 변경은 수정하지 않았다. 미커밋 예산 승인 SQL/테스트, 원본 PDF, 환경변수, 진단용 SQL/응답 원문은 통합 대상에서 제외했다. DB 변경·재처리·유료 AI 호출·PDF 업로드를 다시 실행하지 않았다.

별도 통합 작업 공간에서 전체 검사를 실행한다. 원격 main을 다시 확인하고 일반 fast-forward 푸시만 사용한다.

검증 결과: 통합 작업 공간에서 `npm run check -- --maxWorkers=2` 종료 코드 0. 타입 검사 성공, 린트 오류 0(기존 경고 21개), 204개 파일·1,746개 테스트 통과. src/scripts/tests/supabase는 기존 운영 커밋 703024cf3와 동일함을 확인했다.
