# 백오피스 UI와 최신 촬영·채점 로컬 통합 (2026-11-02)

최종 통합본 `npm run check -- --maxWorkers=2 --testTimeout=30000` 통과: 타입 검사·린트 오류 0, 기존 경고 21, **242파일 / 1,966개 테스트 통과**. `git diff --check`도 통과했다.

## 기준과 보존
- 원격 main 확인 기준: `4f866d6d751ea4f38ce17b2fd3212c12aafd8516` (촬영 커밋 `bfe1082ffd3f0e3b95399bf8d1ea56f90e9cde29` 포함).
- 기존 작업 사본 HEAD `cfd4a008ed70c8a83da5414eabf9b81dadb580c2`와 UI 미커밋 파일을 먼저 `tmp/capture-style-integration-20261101/before/` 및 `working.diff`에 백업했다. 원격 변경 209개 파일을 대조하고 실제 충돌 12개 파일을 결합했다. 이후의 main 작업도 원격 확인 시점 내용으로 보존했다.
- Git HEAD·인덱스는 바꾸지 않았다. HEAD를 main으로 이동하는 mixed reset과 일괄 줄바꿈 변환은 자동 승인 검토가 거절해 실행하지 않았다. 실제 파일을 원격 아카이브와 비교하는 방식으로 검토한다. 커밋·푸시·배포 없음.

## 결합한 계약
- 독해·단어 일괄은 사진별 이름란과 학생 확인 후 처리한다. 학생 변경 시 확인 해제, 중복·미매칭 차단, 실패 재시도에서 완료 학생 제외를 유지했다. 개별은 선택 학생에게 바로 처리한다.
- 학생별 grade_version 해시와 성공 버전만 연결하는 공통 저장 큐를 유지했다. UI의 임시저장/메타데이터/전체 저장과 단어 개별 수정·재채점은 같은 주차 순서로 처리한다.
- UI 입력 스냅샷은 값만 복사하고 버전 객체 연결은 유지한다. 임시저장 뒤 큐에 쌓인 메모가 성공 버전을 이어받는 회귀 테스트를 추가했다. 숙제 PATCH는 숙제만 보내 메모를 덮지 않는다.
- OCR의 고유 photoPath를 로컬 행에 연결하고 사진 실재 검증·답안/사진의 원자 저장을 유지했다. 성공 후 조회는 편집 보존 병합을 사용하며 실패 시 입력·기존 결과·원본을 유지한다.
- AI 응답 누락·중복·grading_failure는 저장 성공으로 취급하지 않고 전체 실패로 처리한다. 기존 부분 저장 성공 표시는 제거했다.
- 출결과 시험 응시는 독립적으로 유지한다. 구형 present=false는 삭제 명령이 아니며, 미응시 null·실제 0점·답안 없는 수동 0점 보존을 메모리 PostgreSQL에서 확인했다.
- UI AnswerWorkspace의 좁은 화면 Sheet에는 기존 sr-only Title/Description을 유지했다. 중복 패치를 넣지 않고 실제 aria-describedby 대상 설명을 촬영 경계 테스트에서 확인했다.
